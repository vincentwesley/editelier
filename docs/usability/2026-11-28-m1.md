# M1 usability walkthroughs + design review (2026-11-28)

Next-session step 5. Both walkthroughs drove the **real app** (debug + `agent` build, off-screen window, null audio sink) through `e2e-app/test/walkthrough.spec.mjs`, which takes an agent `screenshot` (PrintWindow, so the native wgpu preview is included) at every step into `qa-output/walkthrough/` (gitignored, not committed). Media came in through the agent's `import_media` (the shell's own drop path); native pickers can't be driven, and the export folder picker answers with `EDITELIER_TEST_EXPORT_DIR`.

Severity: **Blocker** stops the task, **High** confuses or misleads most people, **Medium** slows them down, **Nit** is polish.

## Walkthrough A: first-time user (never edited before), buttons only

Steps: launch, Welcome "What are you making?" (YouTube video), Start editing, import a/b/c.mp4 + tone.wav, `+` each clip onto the timeline, Trim start at the playhead, Split, Delete, Add title and type its text, `+` the music, Export (Choose folder, Export, Done).

| # | Finding | Severity | Status |
|---|---|---|---|
| A1 | Empty timeline is a blank lane: nothing says clips go there or how (research 03 §6 asks for a drop-zone hint). | High | **Fixed**: the video lane says "Import clips in the Media panel, then drag them here", then "Drag a clip here, or press + next to it in Media" once media exists. |
| A2 | "Trim start" / "Trim end" / "Delete" don't say they work at the playhead, and no button shows its key. | High | **Fixed**: every action button gets a hover title from the action list plus its key in the active key set, e.g. "Trim clip start to playhead (Q)". |
| A3 | Export dialog: a long picked folder pushed "Choose…" out of the dialog and added a horizontal scrollbar. | High | **Fixed**: the folder ellipsizes (full path on hover); "Choose…" stays put. |
| A4 | At 1280x720 the Welcome's only action, "Start editing", sat below the fold. | High | **Fixed**: short windows (≤ 52rem tall) get a compact Welcome (smaller format previews, tighter spacing); the button is visible at 1280x720. |
| A5 | "Saving…" shows for long stretches while editing (autosave runs every 3 s after the last edit), then "Saved 3:24 PM". It reads as stuck while you keep working. | Medium | Deferred: say "Autosave on" until the first save, or show "Saved" with a short delay. |
| A6 | Music longer than the video runs past the last clip with no hint that it'll be cut (or not) on export. | Medium | Deferred: show the timeline end on the music lane, or offer "Trim music to video". |
| A7 | Delete gives no feedback beyond the clip disappearing (no "Deleted b.mp4. Undo" toast). | Medium | Deferred (Undo is visible in the top bar). |
| A8 | Drop-frame timecode `00:00:00;00` (semicolon) is opaque to beginners. | Nit | Deferred: plain `0:04.13`-style time for the Editelier key set, SMPTE for the pro sets. |
| A9 | Inspector canvas select truncates "YouTube video (16:9 landsca…" at 1280 wide. | Nit | Deferred. |
| A10 | The FFmpeg-missing error toast says "Reinstall Editelier": accurate for users, but in dev it means `EDITELIER_FFMPEG_DIR` isn't set. | Nit | Noted (dev-only). |

Result: the whole flow completes with buttons only and the export probes right; no dead ends.

## Walkthrough B: switcher from a pro editor (pro-style keymap)

Steps: Welcome, "Coming from another editor?" pro-style keys, Start editing, import + add 3 clips, `?` sheet, `L` play / `K` stop, `Ctrl+K` split, `I` / `O` marks, `Shift+Delete` ripple delete, `Ctrl+M` export.

| # | Finding | Severity | Status |
|---|---|---|---|
| B1 | The inspector's hints were hard-coded to the simple key set: "S splits at the playhead", but in the pro-style set S toggles snapping. A switcher following the hint turns snapping off instead. | High | **Fixed**: the hints show the active set's keys (Ctrl+K / Shift+Delete / ?) and re-render when the key set changes in the shortcuts sheet. |
| B2 | Export silently used the I/O range: set marks earlier, forget them, export only a slice. | High | **Fixed**: the dialog says "Only the marked part is exported: 00:00:01;14 to 00:00:04;13." with an "Export the whole timeline" button that clears the marks. |
| B3 | The I/O range was a faint 6 px strip on the ruler only, easy to miss. | Medium | **Fixed**: the range shades all tracks, the ruler strip is stronger, and in/out get end ticks. |
| B4 | No "extract/lift the marked range" (pros expect I/O + delete to remove the range); Shift+Delete removes the clip under the playhead. | Medium | Deferred (feature): `range.extract` / `range.lift` in the core + `'` / `;` keys. |
| B5 | J/K/L, I/O, Ctrl+K, Shift+Delete, Ctrl+M and `?` all work as expected; the sheet lists the active map and can switch it. | n/a | OK. |
| B6 | No visible marker of which key set is active outside the `?` sheet. | Nit | Deferred: show it in "All actions" header. |

## Design review (dark + light; default window, 1280x720 and 1920x1200)

Method: vin-workflow design-review against `ui/src/house/tokens.css` and the house principles; 2 rounds (shoot, fix, re-shoot). Sizes are emulated over msedgedriver's CDP (`Emulation.setDeviceMetricsOverride`): `setWindowRect` stops WebView2 painting off-screen and there's no BiDi. In emulated shots the native preview keeps the real DPI, so it sits off its box; that's a capture artefact, not a layout bug.

- Holds up: dark default, square corners, pixel-frame cards (formats, presets, dialogs), offset-shadow primary buttons, tokens-only colour in both themes, light theme readable, About credits card + logo radios render in both themes, dialogs fit at 1280x720.
- Fixed: A3, A4 (layout); B3 (range visibility).
- Nits, deferred: editor tool buttons are 36 px (a deliberate desktop-pointer density, below the 44-48 px house target; revisit with the 150% DPI check); export dialog opens with focus on the close button instead of the primary choice; the `kbd` chips in the inspector are small at 1080p.

## Checks

- `ui`: `npm run check` (typecheck + lint + 31 unit), `npm run build`, `npx playwright test` (56 headless) pass.
- `e2e-app`: full suite 15/15 (flows 9, walkthrough 3, welcome 3) against the debug + `agent` build.
- `walkthrough.spec.mjs` drives the DOM with `execute()` rather than `$()`/`click()`: `@wdio/tauri-service` probes for its plugin (~7 s) before every element command, which made a 30-step walkthrough crawl. The older specs still pay that cost; switching them is a cheap speed-up.
